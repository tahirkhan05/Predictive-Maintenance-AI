## 1. Introduction

Predictive Maintenance (PdM) is a proactive equipment management paradigm that evaluates the condition of industrial machinery by performing continuous or periodic equipment condition monitoring. Unlike reactive maintenance (repairing equipment only after it fails) or preventative maintenance (servicing equipment on fixed time schedules regardless of actual wear), predictive maintenance uses data-driven machine learning algorithms to anticipate mechanical failures before they occur.

---

## 2. Problem Statement

Modern manufacturing and industrial milling processes depend heavily on high-speed rotating equipment and cutting tools. Unplanned machine failures during production runs can cause sudden operational standstills, broken tooling, damaged workpieces, and dangerous workplace conditions. 

The core challenge addressed by this project is:
> *Can we reliably predict whether an industrial milling machine will experience a failure during operation using real-time sensor parameters, while minimizing false alarms and ensuring high recall for critical failure events?*

---

## 3. Why This Project Was Made

Predicting machine failures provides significant industrial and economic advantages:
- **Reducing Unplanned Downtime:** Early warning alerts give maintenance engineers time to service machines during planned maintenance windows rather than stopping active production lines.
- **Lowering Maintenance Costs:** Replacing worn components before catastrophic breakdown prevents secondary damage to expensive spindles, motors, and bearings.
- **Minimizing Production Losses:** Machine downtime leads to missed production deadlines and ruined material batches.
- **Operator Safety:** Catching tool fractures and overstrain failures early protects factory personnel from flying debris or high-speed equipment seizures.

## 4. Dataset

This project utilizes the **AI4I 2020 Predictive Maintenance Dataset** from the UCI Machine Learning Repository.

- **Dataset Name:** AI4I 2020 Predictive Maintenance Dataset
- **Official UCI Source Link:** [https://archive.ics.uci.edu/dataset/601/ai4i](https://archive.ics.uci.edu/dataset/601/ai4i)
- **Dataset Nature:** A synthetic dataset created by Matzka (2020) reflecting realistic milling machine operational telemetry.
- **Number of Observations:** 10,000 records
- **Missing Values:** 0 (clean dataset verified)
- **Target Variable:** `Machine failure` (Binary: `0` = Normal Operation, `1` = Machine Failure)
- **Class Balance:** Highly imbalanced — 9,661 Normal instances (96.61%) vs. 339 Failure instances (3.39%).

### Key Telemetry Features:
1. **Product Type (`Type`):** Low (L - 50%), Medium (M - 30%), High (H - 20%) product quality variants.
2. **Air Temperature (`Air temperature [K]`):** Ambient room temperature generated around 300 K.
3. **Process Temperature (`Process temperature [K]`):** Machine operating temperature (~10 K above ambient).
4. **Rotational Speed (`Rotational speed [rpm]`):** Spindle speed ranging between 1,168 rpm and 2,886 rpm.
5. **Torque (`Torque [Nm]`):** Cutting torque exerted ranging between 3.8 Nm and 76.6 Nm.
6. **Tool Wear (`Tool wear [min]`):** Accumulated cutting tool wear duration ranging from 0 to 253 minutes.

*(Note: The five failure-mode indicator columns TWF, HDF, PWF, OSF, and RNF are sub-classification flags and were strictly excluded from input training features to eliminate target leakage).*

## 5. Methodology

The machine learning pipeline follows a disciplined, reproducible engineering structure:

```
Raw Telemetry Data (UCI AI4I 2020)
                ↓
Data Loading & Schema Validation
                ↓
Domain Feature Engineering (Physics-Based)
                ↓
Stratified Train/Test Split (80% / 20%)
                ↓
Scikit-Learn Pipeline Preprocessing (StandardScaler + OneHotEncoder)
                ↓
Class-Weighted Model Training & 5-Fold Stratified Cross-Validation
                ↓
Performance Evaluation & Model Selection
                ↓
Single-Screen Web Interface (Flask + Modern HTML5/CSS Dashboard)
```

### Feature Engineering Details:
1. **Temperature Difference (`Temp_Difference` = Process Temp - Air Temp):**
   - *Rationale:* Heat Dissipation Failure (HDF) occurs when the heat generated by the process cannot dissipate fast enough into ambient air.
2. **Mechanical Power (`Power_kW` = Torque × Rotational Speed × 2π / 60,000):**
   - *Rationale:* Power Failure (PWF) occurs when power output drops below 3.5 kW or exceeds 9.0 kW.
3. **Overstrain Index (`Overstrain_Index` = Tool Wear × Torque):**
   - *Rationale:* Overstrain Failure (OSF) is directly governed by the continuous stress product of tool wear time and applied torque.
4. **Torque-to-Speed Ratio (`Torque_Speed_Ratio` = Torque / Speed):**
   - *Rationale:* Flags abnormal high-load stall or slip conditions.

### Handling Class Imbalance:
Because failures account for only 3.39% of the records, models trained naively on raw data achieve deceptively high accuracy (>96%) simply by predicting 0 for all instances. We addressed this through:
- Stratified sampling during train/test split and cross-validation folds.
- Incorporating `class_weight='balanced'` in both linear and tree-based estimators to penalize missed failures proportionally.
- Prioritizing **Recall** and **F1-Score** over plain accuracy.

## 6. Results

We trained and compared two distinct classifiers using 5-Fold Stratified Cross-Validation and an independent hold-out test set (2,000 samples: 1,932 Normal, 68 Failures).

### Model Performance Comparison:

| Metric | Logistic Regression (Balanced) | Random Forest Classifier (Selected) |
| :--- | :---: | :---: |
| **Accuracy** | 86.10% | **98.05%** |
| **Precision** | 18.18% | **65.59%** |
| **Recall (Failure Detection)** | 88.24% | **89.71%** |
| **F1-Score** | 0.3015 | **0.7578** (5-Fold CV: 0.7659) |
| **ROC-AUC Score** | 0.9385 | **0.9869** (5-Fold CV: 0.9815) |

### Test Set Confusion Matrix (Random Forest):
- **True Negatives (Correct Normal):** 1,900
- **False Positives (False Alarms):** 32
- **False Negatives (Missed Failures):** 7 (out of 68 total failures)
- **True Positives (Detected Failures):** 61 (89.71% detection rate)

### Model Selection Rationale:
The **Random Forest Classifier** was selected as the champion model. It detects **89.71% of all critical failures** while drastically cutting false alarms from 270 down to only 32, achieving a balanced **F1-Score of 0.7578** and a **ROC-AUC of 0.9869**. The tight match between 5-fold cross-validation F1 (0.7659) and test F1 (0.7578) proves there is **no overfitting or underfitting**.

### Top Predictive Features:
1. `Torque_Speed_Ratio` (17.41%)
2. `Rotational speed [rpm]` (16.68%)
3. `Power_kW` (14.40%)
4. `Tool wear [min]` (13.32%)
5. `Torque [Nm]` (12.68%)
6. `Overstrain_Index` (11.09%)
7. `Temp_Difference` (7.61%)

## 7. Application

A single-page, responsive web dashboard was built using Flask, vanilla HTML5, modern CSS, and lightweight JavaScript.

### Application Highlights:
- **Telemetry Form & Presets:** Allows users to input customized sensor parameters or instantly click pre-configured test scenarios (*Normal Run*, *Overstrain Risk*, *Thermal Risk*, *Power Overload*).
- **Instant Risk Assessment:** Prominently displays operational status (*Normal Operation* in green vs. *Failure Risk Detected* in crimson red) along with the computed failure probability percentage.
- **Operational Explainability:** Translates mathematical predictions into human-readable physical insights (e.g., explaining tool wear thresholds, temperature differentials, and power draw).
- **Embedded Model Performance:** Shows live accuracy, recall, precision, F1-score, and top feature importance bars on the same screen.
- **Single-Screen Layout:** Configured specifically to fit on one desktop screen for single-screenshot internship submission.
